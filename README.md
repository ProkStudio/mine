## Техника

Все варианты используют одну **неживую Entity**, без мобового AI, здоровья LivingEntity, опыта и мобовой смерти. Старый ID сущности `harvester:combine` сохранён для миграции. Идентификатор варианта хранится строкой, не порядковым номером enum.

| Семейство | Предметы (namespace `harvester:`) | Особенности |
|---|---|---|
| Комбайн | `combine_spawn_egg`, `combine_wide` | Замедленный ход; захват 3/5 блоков; бункер 27/54 |
| Бульдозер | `bulldozer`, `bulldozer_heavy` | Копание перед собой; бункер 27/54 |
| Пикап | `pickup`, `pickup_cargo` | Багажник 27/54 |
| Мотоцикл | `motorcycle`, `motorcycle_touring` | Два места, чуть быстрее пикапа; багажник 9/18 |
| Катер | `motorboat`, `motorboat_cargo` | Тяга только в воде; груз 18/36 |
| Самолёт | `plane`, `plane_cargo` | Разбег и управление направлением взгляда; груз 18/36 |
| Вертолёт | `helicopter`, `helicopter_cargo` | Вертикальный взлёт и висение с расходом топлива; груз 18/36 |
| Дрон | `drone`, `drone_cargo` | Малый пилотируемый летательный аппарат; груз 9/18 |

Названия `combine_spawn_egg` и `combine` оставлены для совместимости: предмет теперь **не SpawnEggItem**.

## Управление

Клавиши ниже — стандартные. Сообщение при посадке в авиацию показывает реальные переназначенные бинды.

- **ПКМ предметом по блоку** — поставить машину. Требуется свободное место и Overworld. Катер ставится на воду; можно ПКМ по поверхности воды.
- **ПКМ по технике** — сесть. Первый пассажир — водитель; второй пассажир мотоцикла не управляет.
- **Наземная техника и катер:** W/S — вперёд/замедленный реверс; A/D — поворот. Камера не задаёт их курс.
- **Авиация:** W — тяга по плавно меняющемуся направлению взгляда; S — торможение, не задний ход. A/D не управляют авиационным курсом. Без W поворот камеры не создаёт горизонтальную тягу.
- **Самолёт:** W для разбега, затем взгляд вверх; Space помогает взлёту. Нужна скорость >0.22 блока/тик (4.4 блока/с). Без тяги самолёт снижается.
- **Вертолёт/дрон:** Space — вертикальный подъём; клавиша спринта (обычно Ctrl) — снижение; без ввода при работающем двигателе — удержание высоты с расходом топлива.
- **Shift** — выйти. Не используйте Shift для снижения в воздухе.
- **Shift + ПКМ** — забрать технику предметом: любым предметом в руке, любому игроку, с полным бункером. Нужен один свободный слот; иначе машина остаётся в мире.
- **Сундук в руке + ПКМ** — открыть грузовой инвентарь. Сундук не расходуется. Это замена старому Shift + ПКМ, который теперь забирает машину.
- **Канистра + ПКМ** — заправить.
- **Набор ремонта + ПКМ** — восстановить до 40 единиц состояния.
- **Краска + ПКМ** — следующий из 16 цветов; краска расходуется вне creative.
- **Ножницы + ПКМ по комбайну** — поднять/опустить жатку визуально. Отдельного транспортного режима без уборки нет: при движении работа автоматическая.

Actionbar водителя показывает топливо, занятые слоты, состояние и предупреждения; авиации — скорость/готовность взлёта, отсутствие ввода и затопление. Открытие GUI сбрасывает клавиши; пакеты принимаются только от первого пассажира и протухают без обновления. При timeout вертикальная авиация удерживает высоту, пока есть водитель и топливо, но не продолжает старую тягу вперёд.

При существенном погружении корпуса/двигателя самолёт, вертолёт и дрон теряют воздушную тягу и получают пассивную водную физику. Полёт под водой не является функцией. Катер использует демпфированную плавучесть по высоте жидкости и боковое сопротивление; тяга на суше запрещена. Реальное поведение переходов требует игрового QA.

## Подбор, повреждения и сохранение

Удары накапливают кратковременное повреждение крепления, как у лодки; при пороге машина превращается в **один предмет с грузом внутри**. Состояние постепенно снижается от ударов, а полностью сломанную технику можно поставить, отремонтировать и заправить. Нет выпадения опыта или отдельного мобового лута.

В `minecraft:custom_data.VehicleState` сохраняются версия формата, тип, топливо, состояние, цвет, положение жатки, задержка рабочего цикла и все слоты с компонентами предметов. Пользовательское имя переносится отдельным компонентом. UUID, координаты, пассажиры, ввод и временное водное состояние в предмет не копируются.

При подборе закрываются экраны бункера. При ошибке сериализации исходная машина остаётся на месте. Предмет с сохранённым состоянием расходуется при постановке **даже в creative**, чтобы не дублировать груз. Новые creative-предметы без состояния можно ставить многократно.

## Топливо и работа

- `fuel_can_small`: 400, `fuel_can_medium`: 1200, `fuel_can_large`: 3200 единиц по умолчанию.
- Канистры не стакаются. При частичной заправке остаток сохраняется в канистре. Пустая канистра сама не пополняется.
- Новая машина появляется без топлива. Уголь и железный слиток больше не используются для обслуживания.
- Основной расход — при фактическом движении; рабочие машины дополнительно расходуют топливо за успешный рабочий цикл.
- **Изменено по новому плану:** работающий авиационный двигатель в воздухе расходует `max(1, movementFuel)` за тик, в том числе при неподвижном висении. Выключенная неподвижная техника на земле не расходует топливо. При пустом баке висение/тяга прекращаются.
- Грязь, слизь, песок душ и мёд замедляют наземное движение.
- За пределами Overworld постановка запрещена, а перенесённая командами техника не движется и не работает. Подобрать её можно.

Комбайн обрабатывает полосу перед жаткой. Поддерживаются зрелые ванильные культуры, какао, ягоды, адский нарост, тростник, тыквы и арбузы. Пересадка резервирует семя из урожая; стебли сохраняются. Тростник снимается сверху вниз в пределах высоты захвата. При нехватке места растение не меняется. Выгрузка — только через инвентарь, без передачи в сундук шнеком.

Бульдозер начинает бурение при тяге вперёд, в том числе вплотную к стене. Число блоков за цикл ограничено. Жидкости, блоки с block entity, неразрушимые и запрещённые конфигом блоки пропускаются. Полный бункер останавливает разбор соответствующего блока, без потери добычи. Добыча рассчитывается инструментом уровня алмазной кирки, без зачарований. Это не интеграция с плагинами регионов; стандартные ограничения изменения мира игроком учитываются.

## Графика, пассажиры и звук

- В GUI/хотбаре — собственные генерируемые 2D-иконки из геометрии техники; в руках — JSON 3D-модели. Современные определения находятся в `assets/harvester/items/`.
- В мире — собственные ModelPart-модели и генерируемые PNG, окрашиваемые материалы, колёса, мотовило, винты и роторы. Подробнее: [CUSTOM-VEHICLE-ART.md](docs/CUSTOM-VEHICLE-ART.md).
- Добавлена клиентская поза: корпус пассажира вдоль машины, ограниченная плавная голова при свободной камере, базовые позы рук/ног; у второго места мотоцикла своя поза. Использование предметов и атаки сохраняют обычные анимации рук.
- **Высота/координаты кресел и кабины ещё не исправлены.** Базовые углы не гарантируют совпадение рук с рулём и не устраняют сидение слишком высоко. Первый/третий вид и работа client-only mixin требуют запуска клиента.
- Колёса используют подписанное перемещение и радиус шины; ступицы совпадают по фазе. Есть плавный визуальный поворот передних колёс (пока оценка по yaw, не реальный steering state).
- Жатка перемещается плавно; роторы/винты разгоняются и останавливаются, диагональные пары дрона вращаются навстречу. Истории анимации раздельны по машинам. Мотовило пока использует старый RUNNING; полный working state, подвеска и согласованный крен ещё в плане.
- **Звук поршня удалён. Штатный двигатель сейчас без звука:** собственные OGG и зацикленный клиентский звук ещё не реализованы. Событие `harvester:engine` сохранено с пустым списком ресурсов.
- Выхлоп вынесен к внешним точкам модели, брызги катера — к корме. Дрон и вертолёт не получают универсальный дым из центра. Пыль/поток роторов/частицы фактической работы ещё в плане.

Отсутствие missing model/texture, обзор камеры, видимость эффектов и правильная поза требуют проверки в клиенте. Ни unit-тесты, ни проверка JSON не заменяют визуальную приёмку. [Статус этапа 2](docs/TRANSPORT-PASSENGER-ANIMATION-STATUS.md).

## Конфигурация

`config/harvester.json` содержит:

- `vehicles.<item_id>`: `speed`, `tank`, `durability`, `slots` (кратно 9, до 54), `workRadius`, `movementFuel`, `workFuel`;
- `fuelCans`: `small`, `medium`, `large`;
- `vehicleLimit`: `maximum` (12) и `radius` (32 блока); учитываются загруженные машины в сфере постановки;
- `digRules`: `maxHardness`, `blocksPerCycle`, `intervalTicks`, `denied`;
- `harvestIntervalTicks`.

Если уже есть старый конфиг, он не перезаписывается: рядом создаётся `harvester.example.json` с расширенной схемой. Старые параметры комбайна используются как миграционные значения, скорость ограничивается сверху 0.20. Для изменения настроек перезапустите сервер. Физику, лимиты, работу и HUD рассчитывает сервер, не клиент.

При уменьшении вместимости уже сохранённый груз не обрезается. Переполненный относительно нового лимита бак не пополняется, пока остаток не опустится ниже лимита.

## Получение предметов — без крафта

Все предметы добавлены в creative-вкладку **Harvester — техника и заправка**. Рецептов нет.

```mcfunction
/give @s harvester:combine_spawn_egg
/give @s harvester:pickup
/give @s harvester:motorcycle
/give @s harvester:fuel_can_large
/give @s harvester:repair_kit 16
/give @s harvester:paint 16
```

Никаких гаражей, станций, асфальта, достижений, GPS, автопилота, радио или AI-работников.

## Миграция и проверка

**Сначала резервная копия мира.** Старый `harvester:combine` читает `Fuel`, `Inventory`, `Health`, `HeaderEnabled`. Сохранённый груз и топливо переносятся. Здоровье, ранее потерянное старым кодом при сохранении, восстановить задним числом невозможно. Откат на старый jar после нового сохранения без восстановления резервной копии не поддерживается.

```bash
bash tests/run.sh
./gradlew clean build
python3 tests/verify_results.py
```

`build` включает JUnit-тесты общего формата состояния (JsonOps, без Minecraft bootstrap), чистые тесты физики/поз/анимаций, автономные правила и проверку ресурсов. Это не полноценный ItemStack/NBT-прогон или запуск Mixin в игре. Verifier требует 31 метод без failures/errors/skips: 4 VehicleStateTest, 11 VehiclePhysicsTest, 7 PassengerPoseTest, 7 VehicleAnimationTest и 2 VehicleVisualResourcesTest. CI использует JDK 21; фактический результат текущего main в этой сессии не получен. Используйте основной jar из `build/libs/`, не `-sources.jar`.

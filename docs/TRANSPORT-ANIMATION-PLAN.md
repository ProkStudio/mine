## Исходный запрос

Пользователь просит больше анимаций для реализма и сообщает: сидя в любом транспорте, персонаж может вращаться во все стороны, как на вращающемся кресле.

Последний известный main до первоначальной записи: f39b3d3f904d7b9bf392d53d974f068cb073d9e8. Перед реализацией перечитать актуальные файлы и другие дополнения в docs/TRANSPORT-*.md.

## Приоритет: исправить посадку, не заперев камеру

- [ ] Отделить ориентацию транспорта, корпус сидящего персонажа, голову и камеру. Сейчас жалоба относится к вращению персонажа на сиденье, а не к требованию полностью отключить обзор.
- [ ] Корпус и таз водителя ориентировать вдоль локальной оси сиденья плюс yaw транспорта. Не позволять туловищу независимо делать полный оборот от движения мыши.
- [ ] Сохранять свободный осмотр камерой; голова визуально поворачивается/наклоняется в анатомически разумном диапазоне относительно туловища. При взгляде назад не выкручивать шею и не разворачивать таз на месте.
- [ ] Руки держатся возле руля/штурвала/рычагов, ноги — у пола/подножек; проверить разные положения управления у мотоцикла, автомобиля, комбайна, катера и авиации.
- [ ] Для второго места мотоцикла задать отдельную пассажирскую позу, не руки водителя и не вращающееся кресло. Привязка тела должна работать у всех пассажиров, не только первого.
- [ ] Не переписывать player yaw/pitch каждый серверный тик ради визуальной фиксации корпуса: это ломает камеру и новое управление авиацией по взгляду.
- [ ] Согласовать авиацию: водитель задаёт направление взглядом, машина плавно поворачивается, тело следует сиденью; голова ограничена только визуально. Наземная техника и катера по-прежнему поворачиваются A/D, не камерой.
- [ ] Проверить Yarn/Fabric 1.21.11: способ задания body yaw/head yaw, пассажирские render states и порядок vanilla-обновления. Не применять вслепую API LivingEntity к самой транспортной Entity.
- [ ] Если нужен клиентский mixin для позы, ограничить его пассажирами CombineEntity; не менять обычного игрока, ванильные лодки, лошадей и другие моды. Проверить mixin-конфигурацию, выделенный сервер и снятие позы после выхода.
- [ ] Проверить посадку из основного плана: реальное положение кресла, открытый верх или достаточная высота крыши, камера не внутри кузова.

## Набор анимаций по семействам

Все амплитуды умеренные. Анимации зависят от действительного движения, ввода и работы, а не бесконечно проигрываются на стоящей выключенной машине.

### Общие

- [ ] Плавный поворот рулевого механизма и управляемых колёс; руль/штурвал связан с вводом, а не случайным временем.
- [ ] Вращение колёс от подписанного пройденного расстояния и радиуса: задний ход вращает их обратно, остановка останавливает. Не путать поступательное вращение и поворот колёс.
- [ ] Небольшой крен и продольный наклон кузова при повороте/разгоне/торможении, сглаженная работа подвески от поверхности.
- [ ] Небольшая вибрация двигателя только при его работе; по умолчанию не трясти камеру игрока ради эффекта.
- [ ] Плавное ускорение и остановка вращающихся механизмов при запуске/остановке; сохранение правильной фазы на границе угла 2π.

### Комбайн

- [ ] Вращение мотовила и движение ножей при фактической уборке, согласованные с топливом и рабочим состоянием.
- [ ] Плавное поднятие/опускание жатки вместо мгновенного скачка; не менять согласованное правило автоматической уборки и не вводить отдельный транспортный режим.
- [ ] Раздельная анимация движения колёс и рабочих механизмов: RUNNING не должен быть универсальным сигналом, заставляющим всё вращаться одинаково.

### Бульдозер

- [ ] Движение траков/катков с разницей скоростей сторон при повороте; без бесконечного скольжения стоящих гусениц.
- [ ] Работа бурового механизма, если он присутствует в актуальной модели, и умеренная вибрация рабочего узла только при копании. Не добавлять фиктивный механизм, не согласованный с моделью.

### Пикап и мотоцикл

- [ ] Передние колёса поворачиваются вместе с рулём, подвеска реагирует на движение.
- [ ] Мотоцикл плавно наклоняется на повороте; водитель и пассажир согласованы с наклоном, не проходят сквозь сиденье и не остаются висеть вертикально отдельно от машины.

### Катер

- [ ] Винт и поворот подвесного мотора связаны с тягой/рулением.
- [ ] Умеренный крен при повороте и дифферент при разгоне, лёгкое покачивание на воде.
- [ ] Визуальное покачивание не должно менять физическую плавучесть, создавать подпрыгивание или маскировать баги из TRANSPORT-WATER-BUGS.md.

### Самолёт

- [ ] Пропеллер, элероны, руль высоты и направления соответствуют режиму полёта/управлению.
- [ ] Сглаженный крен в повороте и тангаж согласованы с направлением полёта. На земле не проигрывать воздушный крен как в воздухе.

### Вертолёт и дрон

- [ ] Главный/хвостовой роторы вертолёта и винты дрона разгоняются/останавливаются плавно; для дрона предусмотрены разные направления вращения.
- [ ] Умеренный наклон при горизонтальной тяге, возврат к ровному висению после отпускания управления.
- [ ] Затопленный или выключенный аппарат не проигрывает анимацию нормального powered flight; согласовать с водным запретом и звуком.

## Архитектура и ограничения

- [ ] Сначала проверить VehicleGeometry, CombineRenderer/CombineRenderState, CombineEntity и клиентскую регистрацию. В предыдущем коде некоторые группы уже вращаются; дополнять и исправлять их, не создавать дубли.
- [ ] Определить явные состояния: скорость/руление, engineActive, working, grounded/inWater, подъём жатки, обороты механизмов. Передавать только необходимые данные, остальные визуальные величины вычислять на клиенте со сглаживанием.
- [ ] Использовать отдельные pivots/иерархию частей и постоянную геометрию. Не перестраивать все ModelPart каждый кадр.
- [ ] Учитывать отложенную очередь рендера 1.21.11: не менять общий mutable ModelPart для разных сущностей так, чтобы чужая поза протекала в следующий draw. Использовать безопасные render states/матрицы согласно API.
- [ ] Согласовать наклон кузова с пассажиром и точками эффектов. Отдельный наклон только модели без согласования сиденья может снова привести к персонажу над крышей.
- [ ] Не менять hitbox резкими декоративными трансформациями и не создавать клиент-серверную рассинхронизацию.
- [ ] Статическая миниатюра в руке и 2D-иконка остаются самостоятельными кастомными ресурсами; новый риг не должен ломать их генерацию.
- [ ] Работать через GitHub MCP без терминала/clone/curl, как оговорено ранее. Если без запуска клиента не удаётся проверить позу/анимацию, явно оставить игровой QA открытым.

## Приёмка

- [ ] Поворот камеры на полный круг не раскручивает корпус сидящего персонажа. Голова и руки не выворачиваются; камера не застревает.
- [ ] На земле взгляд не поворачивает транспорт; в авиации согласованное управление взглядом продолжает работать.
- [ ] Проверка вида от первого/третьего лица и со стороны другого игрока, двух мест мотоцикла, посадки/выхода, переподключения, pickup/reload.
- [ ] Стоянка, разгон, торможение, задний ход, повороты, работа, пустой бак, поломка и погружение дают ожидаемые анимации.
- [ ] Unit-тесты нормализации относительных углов, знака вращения колёс, сглаживания, ограничения наклонов, остановки механизмов. Без Minecraft Bootstrap в обычном JUnit.
- [ ] Компиляция main/client, существующие тесты состояния и ресурсов, выделенный сервер, затем реальные видеопримеры всех восьми семейств. Указывать проверенный SHA; не выдавать написанный план или код за проверенную анимацию.

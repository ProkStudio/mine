# Этап 3: собственный звук — код и автономная проверка

Дата: 2026-09-05. Это НЕ объявление о завершении всего транспортного плана.

## Что добавлено

- Шесть оригинальных процедурных профилей: общий двигатель, мотоцикл, катер, самолёт, вертолёт, дрон. Это синтез, не записи настоящих моторов и не заимствованные звуки.
- `tools/src/VehicleAudioGenerator.java` создаёт настоящие Ogg Vorbis: mono, 16000 Hz, двухсекундные циклы, кодирование libvorbis quality 2. Исходные частоты периодичны на границах цикла. Наличие слышимого шва и характер звучания ещё требуют прослушивания в игре.
- Каждый файл проходит полное обратное декодирование: ровно 32000 PCM-отсчётов, ненулевой сигнал, отсутствие цифрового клиппинга; проверяются Ogg/Vorbis identification header, mono и частота. Создаются SHA-256 manifest и сведения о версии кодировщика.
- `processResources` вызывает генератор; в jar должны попадать бинарные `.ogg`, а не текст под видом звука. Неполные экспериментальные base64-переносы удалены из текущего дерева; сборка их не использует.
- Клиентский `MovingSoundInstance`: координаты машины, плавные volume/pitch, затухание при выключении, остановка при удалении/выгрузке/смене мира. Одновременно не более 16 голосов, включая затухающие. Отбор ближайших машин в пределах 32 блоков.
- После перезагрузки звука/отказа звукового канала повторная попытка ограничена примерно одной секундой и не зависит от того, получает ли отвергнутый звук свой `tick()`.
- Своя настройка `config/harvester-client.properties`: `engineVolume=0.65`, допустимо 0..1, 0 отключает. После правки нужен перезапуск клиента. Дополнительно применяется категория Friendly Creatures/Дружелюбные существа.
- Раздельные sound events и RU/EN subtitles. Поршневые one-shot звуки не возвращены.
- Ресурсный JUnit-тест теперь требует шесть OGG и сверяет SHA-256, вместо прежнего требования пустого `sounds`.

## Кодировщик и лицензии

По умолчанию используется build-only JAVE **4.2.0**, `jave-core` и соответствующий платформенный `jave-nativebin-*` из Maven Central. Проверены исходный tag 4.2.0 и интерфейс `DefaultFFMPEGLocator`; разрешение этих Maven-артефактов здесь не выполнено из-за недоступной сети. JAVE — GPLv3; FFmpeg имеет собственные лицензии конфигурации сборки. Эти библиотеки и исполняемые файлы НЕ входят в runtime classpath мода и НЕ упаковываются в jar: это инструменты сборки. Исходный синтезатор и сгенерированное аудио — **CC0-1.0**, как фактический LICENSE репозитория. Первоначально ошибочно указанная MIT исправлена; лицензию остального репозитория не меняли.

Можно явно выбрать установленный кодировщик:

```bash
./gradlew clean build -PvehicleFfmpeg=/absolute/path/to/ffmpeg
```

Путь должен вести к исполняемому файлу с `libvorbis`. В этом режиме build-only Maven-конфигурация JAVE пустая. В обоих режимах отсутствие кодировщика/ошибка кодека/декодирования останавливают сборку, а не создают тихую заглушку.

Побайтовая воспроизводимость OGG между разными запусками/версиями кодека НЕ заявлена: serial контейнера и кодек могут менять байты. Manifest вычисляется для фактически полученных файлов. Исходный PCM синтезируется с фиксированным seed каждого профиля.

## Что действительно выполнено локально

С разрешения пользователя использован терминал. Доступен Corretto **25.0.4**; команда `javac` отсутствует, но компилятор доступен через модуль `jdk.compiler`:

```bash
java -m jdk.compiler/com.sun.tools.javac.Main --release 21 -d /data/audio-classes /data/VehicleAudioGenerator.java
java -cp /data/audio-classes VehicleAudioGenerator /data/generated-audio /usr/local/bin/ffmpeg
```

- Компиляция генератора с `--release 21`: PASS. Запуск — на Java 25, не на JDK 21.
- Git blob локально проверенного исходника после исправления лицензионного текста: `e207d69e8814de56a688fde2a1ebeccc0baeac6c`.
- FFmpeg **7.0.2-static**, libvorbis: кодирование и полное декодирование всех **6/6** файлов PASS, по 32000 отсчётов, mono/16000 Hz, без цифрового клиппинга. Лог: [AUDIO-VALIDATION-2026-09-05.log](AUDIO-VALIDATION-2026-09-05.log).
- Дополнительная проверка ffprobe на предыдущем прогоне того же синтеза подтвердила 2.0 секунды для всех шести файлов. Граничный скачок PCM у каждого меньше максимального внутреннего скачка; это численная проверка, не доказательство отсутствия слышимого шва.
- Это НЕ JUnit, НЕ сборка Minecraft и НЕ запуск `MovingSoundInstance` в игре.

## Открытые пункты исходного плана

1. Реальный контракт пассажирского attachment, координаты кресел, геометрия/просвет кабин и проверка от первого/третьего лица. Текущая поза тела НЕ устраняет слишком высокую посадку.
2. Разделение синхронизированных `engineActive`, фактического `working` и реального steering. Сейчас звук использует прежний RUNNING через `isHarvesting()`, а pitch — скорость, не обороты двигателя.
3. Полная механическая анимация, подвеска/крен, согласованные пассажиры и эмиттеры.
4. Поверхностная пыль, ограниченный наземный/водный поток роторов и частицы фактической работы.
5. Зелёный build на точном SHA, все 31 JUnit-метод без skips, dedicated server и игровой QA, включая груз/сохранение/Shift+ПКМ/воду/авиацию/смену мира/перезагрузку ресурсов.

Эти пункты не помечены выполненными. До основной игровой установки нужны доступ к зависимостям и проверка собранного jar на копии мира.

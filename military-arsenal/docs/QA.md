# Приёмка Military Arsenal

## Подтверждено

На исходной реализации ядра локально выполнены:

- Компиляция чистых Java-классов с `--release 21`.
- 17 678 assertions: каталог, границы геометрии, сохранение количества патронов, полуавтомат/автомат/очередь, подавление повторов в одном тике, cooldown при смене оружия, анимационные кривые.
- Генерация 350 JSON-моделей, 30 item definitions, 27 PNG-текстур, 30 уникальных рецептов и RU/EN локализации.
- Проверка ссылок на модели/текстуры, размеров PNG, положительных cuboid-габаритов, допустимого диапазона координат, display contexts, рецептов и damage tags.
- Генерация и обратное декодирование 12 mono Vorbis-звуков; тишины, обрезанных данных и клиппинга не обнаружено.
- Созданы 39 отдельных offline-превью моделей и примерных кадров. Осмотрены не все; полный визуальный QA не заявлен. Это не скриншоты Minecraft.

**Полная Fabric-сборка, JUnit и создание remapped jar также успешно выполнены в GitHub для первого полного коммита `4eb0ff8f055dbd71689fcd7f1a91a476c5984783`.** [Успешный прогон](https://github.com/ProkStudio/mine/actions/runs/34050558022). Он не заменяет проверку новых коммитов или запуск в игре.

Рабочая среда перезапустилась во время визуальной проверки; локальная временная копия потеряна, исходники к этому моменту были сохранены в GitHub. Последующие исправления следует проверять по результатам CI актуального коммита. По осмотру исправлены скрытый торец ствола пистолета, геометрия скоб, вынимаемый магазин и пересекающиеся торцы трубчатых деталей. Новый полный визуальный прогон не подтверждён.

## Автоматическая проверка в GitHub

Workflow `.github/workflows/military-arsenal.yml` отдельно собирает этот модуль, запускает JUnit и требует четыре реально выполненных кейса без ошибок/пропусков. Check **Military Arsenal diagnostics** содержит журнал. Архив Actions содержит jar только при успешной сборке и отчёты.

Существующий workflow `build` относится к транспортному модулю в корне. Его результат не заменяет проверку Arsenal; сам транспортный код этим PR не исправляется.

## Обязательная ручная проверка — пока не выполнена

### Установка и ресурсы

- [ ] Чистый клиент Fabric 1.21.11 с нужным Fabric API запускается без ошибок mixin/resource loading.
- [ ] Отдельный dedicated server стартует без загрузки клиентских классов.
- [ ] Все 30 предметов в creative-вкладке имеют правильные имена, 3D-модели и текстуры.
- [ ] Все 30 рецептов и условия открытия книги загружаются без ошибок datapack.
- [ ] Все 12 звуков слышны, позиционируются, меняют громкость с расстоянием; работают субтитры RU/EN.

### Каждое из 16 орудий

- [ ] Проверить первый/третий вид с правой и левой ведущей рукой.
- [ ] GUI, хотбар, земля, item frame и glow item frame: нет обрезания, мерцания и отсутствующих текстур.
- [ ] Предмет на земле не воспроизводит застрявший кадр перезарядки.
- [ ] Выстрел, холостой щелчок, начало/середина/конец перезарядки, смена оружия и осмотр.
- [ ] Прицел не уходит относительно игрового луча; тест разных FOV, GUI scale, 16:9 и ультраширокого экрана.
- [ ] Затвор/цевьё/барабан/магазин двигаются по назначению. Пальцы и руки не проходят явно сквозь оружие.
- [ ] Спринт отменяет действие, отпускание ЛКМ останавливает AUTO. SEMI требует нового нажатия; BURST даёт ровно три.

### Боеприпасы и сохранность

- [ ] Survival: полная и частичная перезарядка, последний патрон, пустой инвентарь, совместимые и несовместимые патроны.
- [ ] Во время перезарядки: переключить слот, выбросить предмет, передать другому игроку, открыть контейнер, умереть, выйти, сменить измерение.
- [ ] Ни дублирования, ни потери патронов. Уже загруженный магазин остаётся в выброшенном/сохранённом оружии.
- [ ] Перезапуск мира сохраняет магазин, тип патронов и режим; не восстанавливает старый таймер стрельбы.
- [ ] B не превращает заряженные обычные патроны в AP. Пустой Atlas циклически выбирает четыре типа ракет.
- [ ] CREATIVE корректно заряжает без инвентарных патронов; survival после смены режима не получает бесконечный боезапас.

### Попадания и ограничения

- [ ] Тонкая стена/стекло/дверь/сущность вплотную: raycast не наносит урон через препятствие.
- [ ] Дробь по одной цели суммируется один раз; несколько целей не делят один ошибочный hitmarker.
- [ ] Скорострельное оружие не теряет выстрелы из-за vanilla hurt cooldown.
- [ ] HE, AP, дымовая и учебная ракета различаются поведением. Учебная не наносит урон.
- [ ] Взрыв не портит блоки и не поджигает мир; проверка препятствий ограничивает площадной урон.
- [ ] PvP по умолчанию выключен; при включении учитываются обычные ограничения игры и friendly fire.
- [ ] Поведение собственного взрыва около стрелка ожидаемо.
- [ ] Harvester: обычный урон через Entity.damage, отсутствие конфликтов поз пассажира; отдельной модели бронирования не обещается.

### Сеть и производительность

- [ ] Два клиента видят чужие выстрелы, анимации, позы, звук и летящие ракеты.
- [ ] Искусственная задержка/потеря пакетов: не продолжается старая стрельба после тайм-аута.
- [ ] Повтор пакета не ускоряет огонь; смена слота не снимает длинный cooldown.
- [ ] Выход игрока/выгрузка чанка/смена мира прекращают старые эффекты и не оставляют утечки.
- [ ] Лимиты дыма и снарядов удерживают нагрузку; длительная автоматическая стрельба не создаёт неограниченного числа частиц/состояний.

Не отмечайте пункты выполненными по одному только чтению кода или результату build. Для багрепорта нужны название оружия, действие, режим игры, версия Java/Fabric и `latest.log`/crash report.

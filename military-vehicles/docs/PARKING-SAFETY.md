# Парковка и одиночный экипаж — 0.3.0-alpha.3

Рабочая ветка: `work/military-vehicles-autonomous`, база `feature/military-vehicles` на `b1a969f5ed8929f081ef73d13c3696c84a4948ea`. Это следующий alpha-срез, не stable и не подтверждение игровой приёмки. Основная ветка и другие модули не изменяются.

## Найденные дефекты и исправление

До этого `TruckEntity.pickup` сравнивал только квадрат горизонтальной скорости с порогом. Вертикальное падение не блокировало ручную упаковку; сравнение `NaN > limit` также не блокировало её. Ветка смены одиночного поста в `VehicleSystems.accept` проверяла горизонтальную стоянку, но не контакт с землёй и воду.

Новый чистый `VehicleParking` принимает **x, y, z отдельно**, чтобы вызывающий код не мог незаметно подставить только горизонтальный квадрат. Оба серверных вызова передают один снимок `getVelocity()` и актуальные признаки земли/воды. Все компоненты и их квадратная сумма должны быть конечными.

- Ручная упаковка: без пассажиров, без блокировки опор, на сухой земле, полная скорость не выше 0,015 блока/тик. Исходный допуск `.000225` сохранён.
- Смена поста: вооружённая машина, ровно один фактический первый пассажир, сухая земля, полная скорость не выше 0,005 блока/тик. Исходный допуск `.000025` сохранён.
- Для смены используется фактический первый пассажир, не его effective seat: одиночный наводчик остаётся тем же первым пассажиром. Сброс ввода и остановка двигателя после успешного переключения сохранены.
- Отказ происходит до создания/вставки упакованного предмета и до изменения состояния поста. Проверки переполненного инвентаря, карантина неподдержанного сохранения, меню, наблюдателей и полномочий игрока остаются на месте.
- Автоматический дроп разбитой машины, сериализация v1, имена/груз/топливо/fuelTicks, ID, вместимость, баланс, модели, звук и сетевые пакеты не изменены. RU/EN уточняют требование сухой земли.

Это проверяемые дефекты условий в исходниках, **не запись воспроизведения в Minecraft**.

## Автоматические проверки

`VehicleParkingTest` добавляет 10 обязательных JUnit-методов. `ParkingCases` — общие реальные проверки production-кода для JUnit и `ParkingSmoke`, без заглушек Minecraft. Покрыты допустимая стоянка, пассажиры/опоры, земля/вода, вертикальное/составное движение, NaN/Infinity/переполнение, границы обоих допусков и права одиночного экипажа.

```bash
# Только новые чистые правила, JDK 21; не требует скачивания Gradle/Fabric:
bash military-vehicles/tests/run-parking.sh

# Полный обязательный gate:
bash military-vehicles/tests/run-core.sh
bash ./gradlew -p military-vehicles --no-daemon --console=plain --no-build-cache --rerun-tasks clean build
python3 military-vehicles/tools/verify_build.py
```

Новый standalone-набор включён и в `run-core.sh`, и в Gradle `check`. Gate требует **122 точных JUnit-метода**: все прежние 112 плюс 10 новых, без ошибок/пропусков; в installable JAR обязателен `VehicleParking.class`. Все прежние проверки ресурсов сохранены. Теперь standalone-наборов шесть.

Локально новый production-код компилировался модулем компилятора Java 25 с `--release 21`: **10 cases, 107 assertions — PASS**. Это не локальный запуск всех JUnit и не полная Fabric-сборка. Локальная среда не разрешила GitHub DNS-загрузку полного checkout/зависимостей; отдельные исходные файлы получены через подключение GitHub и сверены по исходным blob SHA. Для полной сборки нужны результаты CI именно новой вершины, не старые успешные Actions из TUNING-STATE.

## Дополнительная игровая QA — всё открыто

Только отдельный профиль/копия мира; клиент и dedicated server одной версии. Ни один пункт ниже не закрывается чистыми Java-тестами.

- [ ] Для всех восьми машин: остановка на обычном сухом блоке, Shift+ПКМ, один предмет в инвентаре и отсутствие оставшейся сущности; распаковка сохраняет каждый грузовой слот, имя, состояние, топливо и остаток тиков. Проверить после естественного торможения, чтобы остаточная вертикальная скорость не мешала нормальной упаковке.
- [ ] Падение с уступа, верхняя точка подбрасывания и вода: ручная упаковка отклоняется без потери/дублирования машины или груза; после остановки на суше снова разрешена.
- [ ] Пассажиры, полный инвентарь, частично развёрнутые/убирающиеся опоры: отказ не меняет груз, состояние и предметы. После снятия соответствующей блокировки действие снова работает.
- [ ] Танк и самоходка: одиночный водитель → наводчик → водитель на сухой земле; старые W/A/S/D/G не возобновляются сами, двигатель включается только новым намерением. Камера и меню проверяются на реальном клиенте.
- [ ] Та же смена поста в движении, падении/верхней точке, воде и с двумя пассажирами: отказ без изменения поста. Возврат к обычной стоянке восстанавливает возможность переключения.
- [ ] Два клиента: попытки упаковки/посадки/смены поста около одного серверного тика, выход/переподключение, повторная загрузка мира; отсутствие дублей, рассинхронизации и зависших блокировок.

Остальная игровая QA из [QA](QA.md) и [SERVER-RULES](SERVER-RULES.md) остаётся открытой. Визуальная приёмка, реальное поведение коллизий, сохранения мира, звук и производительность этой работой не подтверждаются.

# Серверные правила — 0.3.0-alpha.2

Восемь машин сохранены. Эта итерация добавляет проверяемый баланс и серверную синхронизацию, точный выбор цели обслуживания и защиту от обхода длинной перезарядки упаковкой. Новые типы техники, станции и новая геометрия здесь не заявляются.

## Настройка

Файл `config/militaryvehicles-server.properties` создаётся при запуске **логического сервера**, если отсутствует. Это каталог конфигурации установки Fabric: у dedicated server свой файл; в одиночной игре файл общий для миров одного профиля, а не отдельный на каждый мир. На подключённом клиенте локальный файл не заменяет правила удалённого сервера.

- `/militaryvehicles config` — показать действующие значения; доступно игрокам, файл не изменяет.
- `/militaryvehicles config reload` — загрузить изменения; требуется ванильное разрешение **ADMINS_CHECK** (уровень администратора, обычно OP 3) либо серверная консоль. Используется API разрешений Minecraft 1.21.11.
- **K**, либо назначенная клавиша справки, показывает полученные от сервера значения и параметры текущей машины.

Пример полного файла с прежними значениями по умолчанию:

```properties
schemaVersion=1
weaponsEnabled=true
supportEnabled=true
engineFuelUnits=1
shotFuelCost=5
tankReloadTicks=60
howitzerReloadTicks=100
serviceCooldownTicks=40
transferLimit=600
fuelReserve=200
workshopRepair=100
recoveryFuelCost=40
nearbyVehicleLimit=12
```

| Ключ | Допустимо | Действие |
|---|---|---|
| `weaponsEnabled` | `true` / `false` | Разрешить аркадные PvE-выстрелы; PvP и разрушение блоков не включаются |
| `supportEnabled` | `true` / `false` | Заправщик, мастерская и лебёдка; ручные канистры/ремкомплекты остаются |
| `engineFuelUnits` | 1–10 | Расход за каждые 10 работающих тиков, включая холостой ход |
| `shotFuelCost` | 1–50 | Топливо за выстрел плюс один снаряд из груза |
| `tankReloadTicks` | 20–600 | Перезарядка танка |
| `howitzerReloadTicks` | 40–1200 | Перезарядка самоходки |
| `serviceCooldownTicks` | 10–200 | Задержка после успешного обслуживания |
| `transferLimit` | 1–600 | Максимальный перелив за одно действие |
| `fuelReserve` | 0–2000 | Неприкосновенный резерв заправщика/эвакуатора для служебного действия |
| `workshopRepair` | 1–100 | Максимум ремонта за один грузовой ремкомплект |
| `recoveryFuelCost` | 1–200 | Топливо за успешное подтягивание |
| `nearbyVehicleLimit` | 1–12 | Общий лимит новой постановки в радиусе 48 блоков, не квота на каждый тип |

Уменьшение лимита не удаляет существующие машины. Вместимость, число мест, скорости, registry ID, размеры моделей, диапазоны наведения, радиусы действия/эффектов, квоты звука и формат сохранения v1 не изменяются конфигурацией. Это ограниченный набор правил экономики, а не произвольный редактор физики.

## Проверка и применение

Формат — UTF-8 **без BOM**, до 8192 байт и 4096 символов. Неизвестные или повторяющиеся ключи, другая схема, дробные/отрицательные числа, переполнение, выход за границы, неверные булевы значения и повреждённый UTF-8 отклоняют **весь** файл. Частичный файл дополняется документированными значениями по умолчанию, не остатками предыдущих настроек. Пустой файл означает все defaults.

При ошибке reload остаётся предыдущий неизменяемый снимок; ошибочный файл не перезаписывается. Если ошибка обнаружена при первом старте, остаются defaults с предупреждением в серверном журнале. Файл меняет администратор явно: фонового наблюдателя и автоматической перезаписи нет.

Правила отправляются клиенту при входе и после успешного reload. Пакет только **сервер → клиент**, ограничен по размеру и повторно валидируется. В нём только значения правил, без пути файла, комментариев или сведений о хосте. Клиент сбрасывает снимок при инициализации соединения/отключении; пока снимка нет, справка не выдаёт локальные defaults за серверные правила. Требуется одна версия мода у сервера и клиентов; смешанные версии не заявлены поддерживаемыми.

Все списания и разрешения проверяются сервером. Отключённые системы не расходуют припасы. Текущая перезарядка при reload **не сбрасывается**; следующие действия используют новые интервалы. После восстановления/распаковки действует задержка `max(100, настроенная перезарядка или служебный интервал)`, поэтому упаковка не превращает длинную перезарядку в прежние 100 тиков. Остаток топливных тиков v1 остаётся 0–9, меняется только размер следующего списания; последний остаток бака не уходит в минус.

Резерв ограничивает служебное списание, но не работу двигателя после него. Нельзя трактовать его как гарантированно несгораемый остаток бака.

## Точное обслуживание

Раньше выбиралась ближайшая подходящая машина в широком конусе взгляда. Теперь сервер трассирует луч из глаз игрока и выбирает **первое физическое попадание**. Стена, игрок, иная твёрдая сущность или неподходящая машина перед целью не пропускаются ради другой машины за ними. При равной дистанции выбор устойчив по ID; стена выигрывает равенство с попаданием в сущность.

Цель: без пассажиров, двигатель выключен, опоры убраны, исправное состояние сохранения, на земле, вне воды, практически нулевая полная скорость, до 12 блоков между позициями машин. Наводиться нужно на коллизионный корпус, не только на геометрический центр. Для лебёдки отдельно сохраняется проверка всего перемещаемого объёма. Дальность, свободный путь, загруженные чанки, граница мира и ванильные права проверяются сервером; интеграция со всеми регион-модами не обещается.

Команда от неправильного поста больше не занимает общий слот действия на текущем тике. Запреты движения/опор и разделение водитель/наводчик сохранены.

## Проверки и открытая приёмка

Добавлены **19 именованных регрессий**, общих для `FleetTuningTest` и `TuningSmoke`. Проверяются границы всех параметров, схема, повторяющиеся/неизвестные ключи, UTF-8 и размер, создание и сохранение файла, сохранение последнего корректного снимка, независимость хранилищ, экономические инварианты, запреты систем, задержка восстановления, перекрытие цели и неподвижность.

Локально выполнен `TuningSmoke`: **902373 assertions, PASS**, настоящий Java-код с `--release 21` на доступной Java 25. Это не 902373 игровых сценария и не запуск Fabric. Полный gate требует **112 выполненных JUnit cases** (прежние 93 + 19), пять standalone-наборов и установочный remapped JAR со всеми прежними ресурсами и новыми классами. Результаты полного JDK 21/Fabric CI смотрите у актуальной вершины [PR #6](https://github.com/ProkStudio/mine/pull/6), а не у старых отчётов 0.1/0.2/0.3-alpha.1.

```bash
bash military-vehicles/tests/run-tuning.sh
bash military-vehicles/tests/run-core.sh
bash ./gradlew -p military-vehicles --no-daemon --console=plain --no-build-cache --rerun-tasks clean build
python3 military-vehicles/tools/verify_build.py
```

Открытые игровые сценарии — **не выполнены здесь**:

- [ ] Dedicated server: OP/не-OP/консоль, вход двух клиентов, reload во время перезарядки.
- [ ] Переподключение к серверу с другими правилами и последовательный вход в два одиночных мира.
- [ ] Ошибочный reload при игре: прежние списания и клиентская справка остаются согласованными.
- [ ] Реальная камера/прицел: соседние и перекрывающие машины, игрок между ними, стена, края широких коллизий.
- [ ] Земля/вода/падение, границы чанков и мира, защищённые территории; отсутствие расхода при отказе.
- [ ] Упаковка/загрузка копии мира с длинными перезарядками и неполным топливным шагом.
- [ ] Остальные сценарии [QA](QA.md): весь парк, пассажиры, звук, производительность, сохранения и модпаки.

Alpha остаётся alpha. Изменения не устанавливаются автоматически в активный профиль/мир; EULA, merge, force push и stable-релиз не выполняются.
